# Silly Memories Plus

Расширение SillyTavern для иерархического сжатия истории чата.

Сохранённый чат остаётся исходным источником данных. Расширение формирует компактную копию истории непосредственно перед отправкой запроса модели.

## Как работает память

По умолчанию используются следующие параметры:

- контекст достигает 75% доступного окна — запускается компакт;
- новые 25% окна остаются обычной raw-историей;
- старая часть превращается в L1-блок примерно на 4000 токенов;
- когда непрерывная группа summary-блоков занимает 75% окна, она сжимается в блок следующего уровня;
- триггер и raw-tail вводятся числами и всегда связаны как `trigger + tail = 100%`.

Пример для окна 80k:

```text
60k использованного контекста
  → старые ~40k превращаются в L1 около 4k
  → новые ~20k остаются raw

15 блоков по ~4k
  → один L2 около 4k
```

Активные блоки образуют непрерывный хронологический фронтир. Если источник блока изменился после редактирования, свайпа или удаления сообщения, небезопасная часть памяти перестаёт скрывать raw-историю.

## Ручное объединение блоков

Уровень в шапке активного summary-блока можно нажать, чтобы выбрать его для merge. Выбранные уровни подсвечиваются. Для merge нужна непрерывная группа из двух и более соседних блоков одного уровня:

```text
L1 + L1 + ... → L2
L2 + L2 + ... → L3
L3 + L3 + ... → L4
```

Например, при трёх блоках можно выбрать первые два:

```text
L1-A + L1-B → L2-AB
L1-C остаётся отдельным активным блоком
```

Операция атомарна: новый блок сохраняется после успешной генерации, проверки размера, проверки исходных сообщений и проверки активного чата. Ошибка оставляет выбранные дочерние блоки активными.

Для ручного merge доступны активные соседние блоки одного уровня в summary-режиме.

## Скрытие summary и возврат raw-истории

Кнопка `Hide summary` переключает активный блок в raw-режим:

- модель получает исходные сообщения диапазона `sourceFrom–sourceTo`;
- следующие summary-блоки и новый raw-tail остаются на своих хронологических местах;
- сам блок, его структура и настройки сохраняются в библиотеке;
- `Restore summary` возвращает компактное представление без повторной генерации.

Raw-блок учитывается в планировщике по `rawTokens` — размеру исходной истории. Он разделяет активный фронтир на независимые группы, внутри которых автоматический rollup обрабатывает соседние summary-блоки.

Если выбранные raw-диапазоны вместе с обязательным хвостом превышают доступное окно, запрос блокируется до восстановления одного или нескольких summary. В интерфейсе показывается величина переполнения.

## Настраиваемые промпты

Меню `Summary prompts` содержит три независимых шаблона:

- `Raw chat → L1` — создание L1 из сообщений;
- `Memory blocks → rollup` — объединение блоков в L2 и выше;
- `Oversized result → reduced block` — уменьшение результата, который превысил целевой размер.

Поддерживаются плейсхолдеры:

- `{{target_tokens}}` — целевой размер результата;
- `{{level}}` — уровень создаваемого блока;
- `{{schema}}` — полная ожидаемая JSON-структура.

Пустой шаблон автоматически заменяется соответствующим встроенным промптом. Кнопка `Restore default prompts` сбрасывает сразу все три шаблона.

## Структура summary

Каждый ответ суммарайзера обязан соответствовать строгой JSON Schema и содержать:

- `narrative`;
- `relationships`;
- `importantItems`;
- `characterStates`;
- `locations`;
- `commitments`;
- `openThreads`;
- `resolvedThreads`;
- `worldFacts`;
- `exactTerms`.

Все поля обязательны. Ledger-поля являются массивами непустых строк. Валидный блок создаётся только из полного JSON без лишних полей.

Большой источник обрабатывается token-aware map/reduce. Слишком длинное отдельное сообщение делится по безопасным текстовым границам. Ошибка завершает текущую транзакцию с заданными лимитами и размером чанка.

Размер редактируемого system prompt входит в бюджет каждой стадии. Источники чата, блоки и промежуточные результаты передаются как JSON.

## Модель и лимиты

Для суммаризации можно выбрать отдельный профиль Connection Manager. Дешёвая модель работает через него, а основное подключение чата сохраняет свою конфигурацию. При пустом выборе используется текущий основной API.

Настраиваются:

- бюджет входа суммарайзера;
- полезный лимит выхода;
- целевой размер блока;
- минимальный размер источника;
- роль инжектированной памяти;
- включение структурированного ledger в промпт.

Полезный output budget считается отдельно от резерва скрытого reasoning. Суммарайзер запрашивается с минимальным reasoning effort; в блок попадает только структурированный результат.
