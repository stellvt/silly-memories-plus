# Silly Memories Plus

Расширение SillyTavern для иерархического сжатия истории чата.

Интерфейс доступен на английском и русском и следует языку SillyTavern. В разделе «Состояние и обслуживание» поле «Язык интерфейса» переключает язык расширения без перезагрузки.

Сохранённый чат остаётся исходным источником данных. Расширение формирует компактную копию истории непосредственно перед отправкой запроса модели.

## Как работает память

По умолчанию используются следующие параметры:

- контекст достигает 75% доступного окна — запускается компакт;
- новые 25% окна остаются обычной raw-историей;
- старая часть превращается в L1-блок примерно на 4000 токенов;
- когда непрерывная группа summary-блоков занимает 75% окна или контексту требуется свободное место, она сжимается в блок следующего уровня;
- триггер и raw-tail вводятся числами и всегда связаны как `trigger + tail = 100%`.

Пример для окна 80k:

```text
60k использованного контекста
  → старые ~40k превращаются в L1 около 4k
  → новые ~20k остаются raw

15 блоков по ~4k
  → один L2 около 4k
```

Активные блоки образуют непрерывный хронологический фронтир. Если источник блока изменился после редактирования, свайпа или удаления сообщения, небезопасная часть памяти перестаёт скрывать raw-историю.

Размер нового блока зависит от объёма источника и ограничен заданным целевым размером. Расширение учитывает фактический размер результата и при необходимости объединяет несколько групп памяти. Последние два сообщения остаются в raw-истории.

## Ручное объединение блоков

Уровень в шапке активного summary-блока можно нажать, чтобы выбрать его для merge. Выбранные уровни подсвечиваются. Для merge нужна непрерывная группа из двух и более соседних блоков одного уровня:

```text
L1 + L1 + ... → L2
L2 + L2 + ... → L3
L3 + L3 + ... → L4
```

Например, при трёх блоках можно выбрать первые два:

```text
L1-A + L1-B → L2-AB
L1-C остаётся отдельным активным блоком
```

Операция атомарна: новый блок сохраняется после успешной генерации, проверки размера, проверки исходных сообщений и проверки активного чата. Ошибка оставляет выбранные дочерние блоки активными.

Для ручного merge доступны активные соседние блоки одного уровня в summary-режиме.

## Выбор контекста блока

Кнопка `Use original history` переключает активный блок на исходную историю:

- модель получает исходные сообщения диапазона `sourceFrom–sourceTo`;
- следующие summary-блоки и новый raw-tail остаются на своих хронологических местах;
- сам блок, его структура и настройки сохраняются в библиотеке;
- `Use summary` включает компактное представление.

Raw-блок учитывается в планировщике по `rawTokens` — размеру исходной истории. Он разделяет активный фронтир на независимые группы, внутри которых автоматический rollup обрабатывает соседние summary-блоки.

Расширение освобождает место сжатием доступных summary-блоков и старой истории. Если выбранные raw-диапазоны и последние сообщения всё равно превышают окно, интерфейс показывает величину переполнения и предлагает восстановить summary или увеличить контекст.

## Настраиваемые промпты

Меню `Summary prompts` содержит три независимых шаблона:

- `Raw chat → L1` — создание L1 из сообщений;
- `Memory blocks → rollup` — объединение блоков в L2 и выше;
- `Oversized result → reduced block` — уменьшение результата, который превысил целевой размер.

При объединении модель получает правила устранения повторов и сохранения причин изменений, переходов и актуального состояния. Завершённые события сжимаются до результата и значимых последствий; открытые цели и обещания сохраняются явно. Эти правила входят в бюджет запроса вместе с выбранным шаблоном.

Поддерживаются плейсхолдеры:

- `{{target_tokens}}` — целевой размер результата;
- `{{level}}` — уровень создаваемого блока;
- `{{schema}}` — полная ожидаемая JSON-структура.

Пустой шаблон автоматически заменяется соответствующим встроенным промптом. Кнопка `Restore default prompts` сбрасывает сразу все три шаблона.

## Структура summary

Каждый ответ суммарайзера обязан соответствовать строгой JSON Schema и содержать:

- `title` — короткий заголовок на языке чата;
- `narrative`;
- `relationships`;
- `importantItems`;
- `characterStates`;
- `locations`;
- `commitments`;
- `openThreads`;
- `resolvedThreads`;
- `worldFacts`;
- `exactTerms`.

В запросе заголовок и память создаются одним ответом. Заголовок содержит до 80 символов и используется для отображения блока. Блок без отдельного заголовка показывает начало нарратива. Ledger-поля являются массивами непустых строк. Валидная память содержит полный нарратив и все ledger-поля без лишних ключей.

Большой источник обрабатывается token-aware map/reduce. Слишком длинное отдельное сообщение делится по безопасным текстовым границам. Ошибка завершает текущую транзакцию с заданными лимитами и размером чанка.

Размер редактируемого system prompt входит в бюджет каждой стадии. Источники чата, блоки и промежуточные результаты передаются как JSON.

## Просмотр и регенерация

Вкладка `Active` показывает блоки, используемые в текущем контексте. Вкладка `Archive` содержит дочерние блоки объединений и блоки с изменённым источником. Нажмите шапку блока, чтобы выбрать его, или уровень, чтобы выбрать его для объединения.

`Regenerate block` открывает поле необязательного пожелания. Например: «Сохрани причины изменений в отношениях, убери повторы». `Generate preview` показывает сохранённый блок и новый вариант. `Save replacement` сохраняет вариант вместе с пересобранными зависимыми объединениями; `Discard preview` закрывает просмотр.

Пожелание входит в бюджет всех стадий регенерации. Перед сохранением проверяются чат, память и исходные сообщения. Статус задачи и кнопка `Stop task` находятся над подменю.

## Контекст и закреплённые факты

Шкала над подменю показывает размер summary-памяти, исходной истории, закреплённых фактов и остального промпта. Отметка на шкале обозначает порог сжатия. Рядом указаны свободный объём и расстояние до порога в токенах. Размер остального промпта измеряется при генерации; до этого шкала показывает известную часть контекста. Смена пресета или модели сбрасывает эту оценку.

В меню `Pinned facts` запишите важные факты текущего чата и нажмите `Save facts`. Факты отправляются отдельным сообщением перед историей, сохраняются в экспорте памяти и занимают место в контексте. Факты сохраняют свой текст при сжатии и регенерации блоков. Для удаления фактов сохраните пустое поле.

Закреплённые факты действуют и при выключенном автоматическом сжатии. Если факты и оставшаяся история превышают окно, уменьшите факты или увеличьте размер контекста. `Clear chat memory` очищает блоки и закреплённые факты после подтверждения.

## Модель и лимиты

Для суммаризации можно выбрать отдельный профиль Connection Manager. Дешёвая модель работает через него, а основное подключение чата сохраняет свою конфигурацию. При пустом выборе используется текущий основной API.

Настраиваются:

- бюджет входа суммарайзера;
- полезный лимит выхода;
- целевой размер блока;
- минимальный размер источника;
- роль инжектированной памяти;
- включение структурированного ledger в промпт.

Полезный output budget считается отдельно от резерва скрытого reasoning. Суммарайзер запрашивается с минимальным reasoning effort; в блок попадает только структурированный результат.
